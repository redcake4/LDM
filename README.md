# Latent Space Is Not Flat: Rethinking Latent Structure for 3D Medical Image Synthesis

## Framework

![Manuscript framework](assets/framework.png)

The figure describes the manuscript method. This release keeps the existing full-input shortcut by default
and provides `--main-structure` to study a structure-only shortcut in the same training framework.
The switch implements the manuscript's structural-shortcut idea with the coordinate convention below;
it does not turn the release into a complete reproduction of all manuscript settings.

## Structural shortcut

In an active MDSA block, let `X` be the incoming residual-stream tokens and
`H = modulate(RMSNorm(X), timestep)` the mixer features. The existing detached, windowed rank-r projector
`P_H` is estimated from `H`. Both modes route `S_H = P_H H` into the global branch and
`R_H = H - S_H` into the local branch. Let `M` denote their gated, concatenated, linearly projected output
and `alpha` the existing AdaLN mixer gate.

| Mode | Mixer update before the unchanged FFN |
|---|---|
| Default (`main_structure: false`) | `Y = X + alpha * M` |
| `--main-structure` | `Y = P_H X + alpha * M` |

The enabled mode reuses **the same projector** to form `S_X = P_H X` from the unnormalized residual stream.
It replaces the full-input shortcut; it does not add `S_H` while retaining `X`, or estimate another projector
from `X`. This explicitly adapts the structure-only shortcut in manuscript Eq. (5) to the current pre-normalized
block: Eq. (5) defines its input as `H`, whereas this implementation's outer residual stream is `X`.
At a zero AdaLN mixer gate the enabled block returns `P_H X` before the FFN, so it no longer has the default
block's identity shortcut at initialization. The projected reference remains differentiable with respect to
`X`; gradients through the eigenspace itself remain detached in both modes.

Only the blocks listed in `model.mdsa_blocks` change (release defaults: zero-based blocks 4 and 5).
The flag requires `mdsa_mode: conditioned` or `strict`; `off` and `gate_only` are rejected.
It adds no trainable parameters. Branch routing and gates, rank and window size (release defaults: 8 and 2x4x4), the d1 local operator,
optimizer, sampling, and all other settings remain those of the selected configuration. The projector still
comes from `H` (whose upstream embedding includes source and current state), not the manuscript's separate
condition/feature Gram-matrix combination. The flag also does not enable decomposition in every block,
rank 2, d124 local branches, or the manuscript's training/sampling schedule. Branch outputs are not
reprojected after their learned transformations, so input decomposition does not imply orthogonal outputs.

This is an implementation variant for a controlled structural-shortcut comparison. Runtime checks do not
establish better synthesis quality; that requires matched training and evaluation of both modes. The existing
qualitative images were not generated by this newly added mode.

## Data Preparation

Use Python 3.10+ and a CUDA-compatible installation of PyTorch 2.5+.
Run the following Python commands from the package root in Windows PowerShell or Linux/AutoDL.


| File | Path relative to the package root |
|---|---|
| T1N-to-T1C H5 dataset | `data/h5/t1n__t1c_3d.h5` |
| T2W-to-T2F H5 dataset | `data/h5/t2w__t2f_3d.h5` |
| MAISI autoencoder weights | `ae_assets/maisi_v1/autoencoder_v1.pt` |

Use authorized, locally preprocessed [BraTS-GLI data](https://www.synapse.org/Synapse:syn51156910).
Each H5 file contains disjoint `train/val/test` groups with `source/target` [N,1,D,H,W],
`mask` [N,3,D,H,W], and `subject_id` [N]. Image and mask values must be finite and within [0,1].
The existing 155x256x256 volumes are padded internally and exported at their original size.
The frozen autoencoder uses the pinned [NV-Generate-CT checkpoint](https://huggingface.co/nvidia/NV-Generate-CT/resolve/a481248bbd6462129efb2a3514e142bb95f87b25/models/autoencoder_v1.pt?download=true).
Both the download script and the loader verify its SHA256. Datasets and weights are not bundled.

```bash
python -m pip install -r requirements.txt
python scripts/check_dataset.py --task t1n_t1c --scan
python scripts/download_ae.py
python -u precompute_latents.py --task t1n_t1c --device cuda --resume
```

Precompute the complete latent cache before training; the training script does not create it automatically.
Caches are stored under `data/latents/maisi_v1/`, separately for each task and shared by its P2/P4/P8 configurations.
Use `--task t2w_t2f` to prepare T2 data. For datasets stored outside the package, specify the same
`--h5-path` during data preparation, training, prediction export, and evaluation.

## Run

```bash
python -u train.py --config configs/t1n_t1c_p4.yaml --device cuda
```

To enable the structural shortcut (P2 example):

```bash
python -u train.py --config configs/t1n_t1c_p2.yaml --main-structure --device cuda
```

The same flag works with all six T1/T2 P2/P4/P8 configurations. Alternatively, set
`model.main_structure: true` in YAML; `--no-main-structure` explicitly overrides it to the default method.
Omitting the flag preserves the YAML setting, which is `false` in the shipped configurations.
The enabled mode's automatic run directory ends in `__main-structure`, for example
`outputs/t1n_t1c__ldm__latent-p2__d1__mdsa-conditioned__seed0__main-structure`.
If specifying `--output-dir`, choose a separate directory for each mode. Resume requires the same mode.
The resolved configuration and checkpoint contract record the flag; export reconstructs the mode from
the checkpoint automatically and needs no additional flag. Original standalone checkpoints without this
field are accepted as the default mode after their original contract is validated; they are not silently
converted into structural-shortcut checkpoints.

Select the T1/T2 and P2/P4/P8 YAML configuration in [configs](configs); all use d1 with MDSA enabled.
Results are saved under `outputs/`; repeating the same command resumes training from `checkpoints/last.pt`.
Use a new output directory when changing settings. Legacy voxel-space or d124 weights, and checkpoints from
other patch sizes, are incompatible. Historical P2 checkpoints must also match this package's model contract.

For P2, use `--config configs/t1n_t1c_p2.yaml` or `--config configs/t2w_t2f_p2.yaml` in the training command.
P2 divides the 48x64x64 latent into 24x32x32 tokens (24,576 total), eight times as many as P4, so it requires
more memory and computation. These configurations retain this release's d1 local branch and MDSA settings
(rank 8, blocks 4 and 5 with zero-based indexing); changing the patch size alone does not reproduce all paper settings.
The run directory uses `latent-p2` in place of `latent-p4` in the export example below.
P2 runtime and real-MAISI synthetic workflow checks passed; see [validation details](docs/p2_validation.json).
Recheck with `python scripts/smoke_cuda.py --patches 2` or `python scripts/smoke_pipeline.py --patch 2`
(the latter requires the pinned MAISI checkpoint). These checks do not measure full-dataset quality or convergence.

For the enabled mode, add `--main-structure` to either smoke command and use a fresh pipeline output directory:

```bash
python scripts/smoke_cuda.py --patches 2 --main-structure --output artifacts/main_structure_cuda.json
python scripts/smoke_pipeline.py --patch 2 --main-structure --output-dir artifacts/main_structure_pipeline
```

Validation of the structural shortcut is recorded in [main-structure validation](docs/main_structure_validation.json).

## Evaluation

```bash
python -u export_predictions.py --run-dir outputs/t1n_t1c__ldm__latent-p4__d1__mdsa-conditioned__seed0 --checkpoint best --split test --output-dir evaluation/t1_p4_test --device cuda
python -u evaluate.py --task t1n_t1c --predictions evaluation/t1_p4_test/predictions_test.h5 --split test --output-dir evaluation/t1_p4_test/metrics --device cuda
```

Use the corresponding run directory and task name for other configurations. Export selects the EMA
checkpoint with the best validation score and uses its sampling settings; existing predictions are not overwritten.
Outputs include prediction volumes, diagnostic PNGs, per-subject metrics in CSV, and a summary JSON.
Evaluation requires an exact match between prediction IDs and test-set IDs and excludes padding.
Full-volume and brain metrics are reported separately, with [0,1] clipping, no brain-exterior zeroing,
a PSNR data range of 1, and a uniform 7x7x7 SSIM window. MAE is also computed within the tumor-union mask
and the top-5%-change ROI within the foreground union. Summaries report subject-wise means and sample SDs.
